# 機能設計書

## 1. システム構成

```
ブラウザ
 ├─ index.html          画面の骨組み
 ├─ styles.css          見た目
 └─ js/
     ├─ app.js          画面描画とイベント処理（DOM に依存）
     ├─ store.js        localStorage への保存・読み込み・データ検証
     ├─ tasks.js        ドメインロジック（純粋関数・DOM 非依存）
     ├─ shortcuts.js    iOS ショートカット連携の URL 生成（純粋関数）
     └─ dates.js        日付ユーティリティ（純粋関数）
```

- サーバー側の処理はない。`server.js` は開発用の静的ファイル配信のみ（ES Modules を使うため）。
- 依存関係は一方向: `app.js → store.js → tasks.js → dates.js`。`tasks.js` / `dates.js` は Node のテストから直接読み込める。

## 2. 画面

画面は1ページ構成で、下部のタブで3つのビューを切り替える。

| ビュー | 内容 |
|---|---|
| きょう | ヘッダー（日付・ほし合計）、進み具合バー、きょうのやることカード一覧 |
| やること | 登録済みのやること一覧、追加ボタン、各行の編集ボタン |
| きろく | 直近7日間のスタンプ表、ほし合計 |

追加・編集は `<dialog>` のフォームで行う。

### 2.1 きょうビュー

- カード: アイコン（大）・なまえ・しゅるいの色帯・チェック状態
- タップで完了⇔未完了を切り替える。完了時はカードが緑になり⭐が飛ぶ小演出
- 全件完了で「ぜんぶできた！」のお祝い演出（紙吹雪）を表示
- 予定が0件のときは「きょうのやることはないよ。やることをふやしてみよう」と案内
- 持ち越し中の「いちどだけ」タスクには「まだだよ」バッジを付ける

### 2.2 やることフォーム

| 項目 | 入力 | 制約 |
|---|---|---|
| なまえ | テキスト | 必須、前後空白除去、1〜20文字 |
| アイコン | 絵文字プリセットから選択 | 必須（既定 📝） |
| しゅるい | しゅくだい / おてつだい / じゅんび / そのほか | 必須（既定 しゅくだい） |
| くりかえし | まいにち / ようびをえらぶ / いちどだけ | 必須（既定 まいにち） |
| ようび | 日〜土のトグル | 「ようびをえらぶ」のとき1つ以上 |
| ひにち | 日付 | 「いちどだけ」のとき必須（既定 きょう） |

## 3. データモデル

localStorage キー `kids-task-app/v1` に JSON で保存する。

```jsonc
{
  "version": 1,
  "tasks": [
    {
      "id": "t_lr8x2k_ab12",          // 一意ID
      "title": "けいさんドリル",
      "icon": "✏️",
      "category": "homework",          // homework | chores | prepare | other
      "repeat": { "type": "daily" },   // 下記参照
      "createdAt": "2026-10-27"        // 作成日（YYYY-MM-DD, ローカル日付）
    }
  ],
  // 日付ごとに完了したタスクIDの配列
  "completions": {
    "2026-10-27": ["t_lr8x2k_ab12"]
  }
}
```

`repeat` の形:

| type | 追加項目 | 意味 |
|---|---|---|
| `daily` | なし | 作成日以降、毎日 |
| `weekly` | `days: number[]`（0=日〜6=土） | 作成日以降、指定曜日 |
| `once` | `date: "YYYY-MM-DD"` | 指定日。未完了なら翌日以降も持ち越し、完了した日まで表示 |

### 3.1 設計上の決定

- **ほしの合計は保存しない。** `completions` の総件数から算出する。カウンターとの不整合が起きない。
- **タスクを削除しても完了記録は残す。** もらったほしは減らない。
- **日付はローカル日付の文字列 `YYYY-MM-DD`。** タイムゾーンずれを避けるため UTC 変換をしない。
- 読み込み時に形式を検証し、不正な要素は捨てる。JSON 自体が壊れていれば初期状態で起動する。

## 4. 主要ロジック（tasks.js）

| 関数 | 説明 |
|---|---|
| `isScheduledOn(task, date, completions)` | その日にタスクが表示対象か |
| `tasksForDate(state, date)` | その日のタスク一覧（`{ task, done, carriedOver }`） |
| `toggleCompletion(state, taskId, date)` | 完了⇔未完了を切り替えた新しい state を返す（非破壊） |
| `totalStars(state)` | ほし合計 |
| `weeklySummary(state, today)` | 直近7日の `{ date, done, total }` |
| `validateTaskInput(input)` | フォーム入力の検証。エラーメッセージ配列を返す |
| `createTask(input, today)` / `updateTask(task, input)` | タスク生成・更新 |

state は不変データとして扱い、更新関数は新しいオブジェクトを返す。`app.js` は「state 更新 → 保存 → 再描画」の順で処理する。

### 4.1 「いちどだけ」の判定

```
date < task.repeat.date                 → 表示しない
完了日 d がある場合: date <= d のとき表示（d 当日は完了済みとして表示）
完了日がない場合:   date >= task.repeat.date なら表示（今日より前の予定日なら持ち越し）
```

## 5. iPad ショートカット連携（F-20〜F-22）

外部サーバーを使わず（非機能要求「外部通信を行わない」を守る）、Web アプリと iOS ショートカットの間は
URL スキームとファイルでやりとりする。Web アプリから iOS ショートカットのデータを直接読むことはできないため、
状態は「ショートカット側が持つファイル」に記録する。

```
[このアプリ] やることぜんぶできた → 「あそびにいく」ボタン
     │  shortcuts://run-shortcut?name=きょうのやることかいほう&input=text&text=2026-10-27
     ▼
[ショートカットA: きょうのやることかいほう]
     入力の日付をファイル  iCloud Drive/Shortcuts/kids-task-unlock.txt  に上書き保存

[オートメーション: 制限アプリを開いたとき]（すぐに実行・通知なし）
     ▼
[ショートカットB: きょうのやることチェック]
     kids-task-unlock.txt を読む
     中身 == きょうの日付 → 何もしない（そのまま遊べる）
     それ以外 / ファイルなし → このアプリの URL を開く
```

- ショートカット名とファイル名は固定値として `js/shortcuts.js` に定数で持つ。
- 「あそびにいく」ボタンは、やることがすべて完了していて、かつねるじゅんびモードでないときだけ表示する。
- 日付は `YYYY-MM-DD`（ローカル日付）。日付が変わると記録と一致しなくなるので、自動でカギがかかる。
- 子どもが Safari などから URL を直接打てば解除できてしまうが、低学年向けの抑止としては十分と判断する。
- ショートカット本体は、保護者が F-22 の案内を見て手で作る（iCloud 共有リンクで配布できるようにするのは将来検討）。

### 5.1 保護者の設定手順（F-22 で案内する内容）

1. このアプリを Safari で開き、「ホーム画面に追加」する
2. ショートカット A・B を作る
3. ショートカットアプリの「オートメーション」→「App」で制限したいアプリを選び、「開いたとき」「すぐに実行」を指定して B を実行する
4. スクリーンタイムで、ショートカットアプリと「設定」を保護者のパスコードで制限する

## 6. エラー処理

| 状況 | 対応 |
|---|---|
| localStorage が使えない（プライベートモード等） | メモリ上で動作を継続し、画面上部に「データがほぞんできません」と表示 |
| 保存データが壊れている | 初期状態で起動し、壊れたデータは `kids-task-app/v1.broken` に退避 |
| フォーム入力エラー | フォーム内にひらがなのメッセージを表示し、保存しない |
